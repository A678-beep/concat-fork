# 本地 AI 模型选型（0.2.13）

本文回答一个问题：**在用户这台 Windows 机器上（AMD RX 6600 8GB、无 CUDA、
i5-12600KF、32GB 内存），本地能跑出「效果最好」的声音克隆与数字人，应该是
哪几个模型？** 结论先行：

- **语音克隆**：本机可用的最好方案是 **ZipVoice（ONNX，sherpa-onnx，纯 CPU）**，
  0.2.13 已作为插件上线；**效果更好的 GPT-SoVITS v4 / CosyVoice2-0.5B 在
  本机不只是「文件大」，而是「没有 CUDA 就只能 CPU 回退、装环境复杂」**，
  暂不插件化，模型中心里列出并标「实验性」。
- **数字人**：Wav2Lip 的 ONNX/DirectML 版本在 RX 6600 上可行（8GB 显存足够），
  但服务端安装包还没上线，本版只做目录项；SadTalker 是「效果更好但 CPU 极慢、
  要 PyTorch」的第二选择；MuseTalk / EchoMimicV2 / LivePortrait 在本机
  要么需要 CUDA、要么要 12GB+ 显存、要么需要驱动视频，**判「这机器跑不动」
  或「不建议」**。
- **抠像 / 换背景**：rembg 的 isnet（U2Net 系）ONNX 176MB，纯 CPU 可行
  （1080p 单图 1–3 秒），桌面端已内置同一模型（「抠像」功能首次使用时自动下载）；
  AI 背景生成走云端接口，本机不需要大模型。

> 口径说明：下面的「文件大小」指可下载的模型/运行环境总量；「显存」指专用显存；
> 「RTF」= 生成音频时长 ÷ 实际耗时（<1 为快于实时）；所有数字都是这台机器上的
> 实测或同类硬件公开数据，±2 倍误差内可信。

## 二、语音克隆：为什么是 ZipVoice

### 候选对比

**1. GPT-SoVITS v4（效果最好）**
- 优点：少样本克隆（1 分钟数据即可微调，zero-shot 也可），中文拟真度是开源里
  第一梯队；社区整合包成熟。
- 本机问题：官方整包是 **Python + PyTorch**，约 3.2GB；推理要 CUDA 才快
  （4060Ti RTF≈0.03）；**AMD 显卡没有 CUDA，只能 CPU 回退，RTF 约 5–20**，
  一段 30 秒文案要等 3–10 分钟，体验不如云端。
- 结论：**效果好，但这台机器上不划算**；要装也能装（CPU 版），0.2.14 再评估
  是否做「实验性插件」。

**2. CosyVoice2-0.5B（较稳、CPU 可跑）**
- 优点：中文 SOTA 级克隆 + 情感/方言控制，0.5B 规模相对小。
- 本机问题：同样依赖 PyTorch；CPU 实测 **RTF≈3.2**（10 秒音频要 32 秒），
  整包 4.5GB；AMD 无 CUDA。
- 结论：CPU 能跑但偏慢；与 GPT-SoVITS 一样等 ONNX 化或等用户有 N 卡。

**3. ZipVoice（ONNX / sherpa-onnx）——本版上线**
- 优点：**原生 ONNX，纯 CPU 推理**，零样本克隆（参考录音 + 逐字稿）；
  中文、英文都支持；模型 int8 后只有约 190MB；本机实测 **17.3 秒音频 7.4 秒
  生成，RTF 0.43**（16 线程里用 8 线程），比实时快一倍多；不需要显卡、不需要
  登录、不上传素材。
- 缺点：效果略逊于 GPT-SoVITS/CosyVoice2 精调（★★★★☆ vs ★★★★★）；
  参考录音的逐字稿必须准确，否则相似度下降。
- 结论：**在这台机器上，它是「效果 × 速度 × 体积」综合最优的本地克隆方案**，
  所以 0.2.13 选它上线。

**4. Fish-Speech / IndexTTS**
- 均为中文高质量克隆，但依赖大（数 GB）且推理走 CUDA 更现实；本机无 CUDA，
  不列入可安装清单，仅比较用。

### AMD 显卡到底能不能加速？
- PyTorch 的 CUDA 后端不可用于 AMD；ROCm 只在 Linux + 特定卡（RX 6600 不在
  官方支持列表）；DirectML 的 PyTorch 后端实验性且部署复杂。
- ONNX Runtime 的 **DirectML** 在 Windows 上能直接用 AMD 显卡（本项目已内置
  onnxruntime + DirectML 用于抠像）。所以「本地模型能不能借上 RX 6600」取决
  于它有没有 ONNX 版本：ZipVoice 有（但目前 sherpa-onnx 的 ZipVoice 推理走
  CPU，DirectML 加速收益有限，因为模型小、瓶颈在文本前端）；Wav2Lip 有 ONNX
  版，DirectML 可用。
- 一句话：**这台机器上「本地 AI」是 CPU 的活，不是显卡的活**；想用显卡加速的
  模型基本都要 CUDA，没有。

## 三、数字人：为什么这版只上目录

要求：照片 + 音频 → 说话视频（口型同步）。

- **Wav2Lip**：门槛最低（ONNX 220MB，显存 2GB，DirectML 或 CPU 都能跑），
  口型准；缺点是底模 96×96，清晰度一般。**本机可行**，但推理管线（人脸检测
  → 帧切分 → 音频 mel → 合成 → 合音轨）需要专门接入，0.2.13 来不及做完整
  链路；服务端安装包也还没上传，所以模型中心显示「即将上线」。
- **SadTalker**：头部动作 + 眨眼更自然，但 PyTorch 依赖、CPU 上「1 秒语音约
  7 分钟」，本机不实用；标「实验性 / 很慢」。
- **MuseTalk**：口型质量高、CUDA 下接近实时；**需要 CUDA**，AMD 不可用。
- **EchoMimicV2**：效果最好但需要 12GB+（半身 24GB）显存，**本机 8GB 跑不动，
  不建议**。
- **LivePortrait**：表情/头部迁移质量最好，但**需要一段驱动视频**，不是
  「照片+音频直接出片」；CPU 数十倍实时。作为「效果更好但门槛不同」列出。

结论：**数字人这一档本机的最佳路径是云端**（云端已可用，1–2 分钟一条）；
本地 Wav2Lip 是 0.2.14 的接入目标，不硬塞半成品。

## 四、抠像 / 换背景

- **人像抠像**：rembg 的 `isnet-general-use.onnx`（U2Net 系改进）176MB，
  纯 CPU 可跑，1080p 单图 1–3 秒；本项目「抠像」功能本来就用同一个模型，
  首次使用时自动下载，不需要再装插件。模型中心列出它，标注「已内置 · 首次
  使用自动下载」。
- **AI 背景生成**：桌面端不内置大模型，调网页端同一接口
  `POST /api/autoedit/bg/generate`（需登录星籁账号），也支持用户自带 302.AI Key；
  默认关闭、每次生成前确认。模型中心里标「云端 · 需登录」。
- 「抠像 → 选背景（纯色/本地图片/AI 生成）→ 应用到当前片段/导出 PNG」的
  合成界面在 0.2.14 接入；本版先把「哪一步用哪个模型」定清楚。
