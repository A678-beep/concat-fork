# macOS 移植障碍清单（星籁剪辑 0.5.0）

- 仓库：`F:\concat\src`，HEAD `0c45c13`（main），分支 `feat/macos-port-prep`
- 扫描日期：2026-11-25
- 范围：代码盘点（真实扫描，不猜）、跨平台改造、CI、打包脚本、移植计划
- 不在范围：服务端、重装软件、`main` 分支、无法验证的"已在 macOS 跑通"结论

## 0. 结论

**这个工程不是"Windows 专属应用"，而是上游 Concat 的跨平台架构**（Rust + Slint，
原生支持 macOS / Windows / Linux / Android / iOS）。Windows 专属代码基本都关在
`#[cfg(windows)]` 里，媒体引擎/语音/视觉/窗口层都有 macOS 分支。真正缺的是：

1. **fork 侧的交付链**：没有可运行的 CI、没有 macOS 打包资产/脚本、仓库里所有 shell
   脚本都丢了可执行位；
2. **fork 新增功能的 macOS 形态**：本地 ffmpeg/ffprobe 命令行、星籁账号（DPAPI）、
   本地 AI 插件（`.exe`/内嵌 python）；
3. **真机验证**：Windows 上无法编译 macOS（FFmpeg/whisper 要 Xcode 的 SDK 与
   C/C++ 工具链），只能做 `cargo metadata`/cfg 静态检查。

障碍数量：**P0 = 4，P1 = 6，P2 = 5**（其中 3 项本轮已改造，见 §2 / §4）。
工时合计约 **94 小时**（不含 P3 签名/公证/分发，约另 20 小时）。

## 5. 未验证项（不能声称"已在 macOS 跑通"）

1. **macOS 编译本身**：Windows 上无法完成，只有 `cargo metadata --filter-platform
   aarch64-apple-darwin` 的依赖解析级静态检查。首次真机/CI 编译必留排错时间。
2. **`.app`/`.dmg` 打包脚本**：只能在 macOS 上运行，本轮未执行过；字体/图标/签名
   命令按上游 `build-app.yml:528-681` 的既有做法编写，但仍需真机首跑。
3. **GitHub Actions 工作流**：未在 GitHub 上实际触发过（本地无法跑 Actions）；
   且本机 token 只有 `repo` scope，`.github/workflows/macos-build.yml` 被 GitHub
   拒绝推送，目前只在本分支的本地 commit 里（拒绝原文与解锁办法见
   [02-移植计划.md](02-移植计划.md) §6）。
4. **VideoToolbox 导出、CoreML/Metal AI、Intel Mac ONNX Runtime、中文输入法**：
   全部需要真机验证。
5. **星籁账号在 macOS 的 TLS/WAF 行为**：未测；Windows 上 rustls 会被重置，macOS
   上结论未知，是 P1-2 的最大不确定项。
6. 仓库既有的 fork 代码存在 rustfmt 漂移（fork 没有 CI，见 P0-1）；本分支新增
   代码已用仓库固定工具链 1.93.1 的 rustfmt 校验，未顺带重排无关文件。
